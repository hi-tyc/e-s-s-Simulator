# F-20 全局集成：转场/音频/无障碍

> 状态：final / accepted
> 实现阶段：Phase 6
> 依赖特性：F-01（叙事状态机）、F-02（SceneDirector）、F-03（MainQuestHUD）、F-04（叙事相机）、F-07（辅助设置面板）、F-19（第六章终章）

## 产品能力描述

将六章叙事体验整合为一条完整可通关的游戏通路：章节间转场平滑衔接且可从任意检查点恢复、全程音频混音在各场景正确分层播放、所有无障碍替代输入与字幕在六章中一致生效。玩家得到的是一款从序章到终章体验连贯、可以在任意时刻暂停/恢复并完整通关的游戏，而不是各章功能的拼接。

## 功能边界

**包含：**
- 六章转场的统一 `prepare → commit → cleanup` 三阶段实现（`SceneTransition` 枚举对应 fade、colorTemperatureFlip、mirrorRipple）
- 转场期间存档落点保证：只在 `commit` 前的稳定检查点或 `commit` 完成后写档，不保存中间帧
- 跨章音频混音：各场景环境音切换（教室→走廊→镜像→楼梯间→咨询室→等候区→终章），镜像空间冷调音频正确叠入/叠出
- `AudioCueKind` 补全：`.bell`、`.noteDrop`、`.crying`、`.chair` 等本章专属音效的程序化兜底实现
- `SupportResourceCatalog` 审核日期检查：自研非商业版本降级为 `#if DEBUG` 编译警告，不阻塞 Release
- 全流程无障碍验证：方向字幕在六章统一开关控制、Reduce Motion 下所有转场动画替换为淡入淡出（0.2-0.4s）、键盘焦点在 HUD/对话/三灯/资源卡的朗读顺序与视觉顺序一致
- 全状态组合测试门禁：六章通关状态矩阵覆盖测试（见设计文档 §必测状态矩阵）
- 发布门禁：`SupportResourceCatalog.reviewedAt` 超过 6 个月时在 Debug 构建输出编译警告

**不包含：**
- 各章具体叙事步骤逻辑（分别属于 F-06 至 F-19）
- 第六章支持网络图、结局文字、求助资源卡（F-19）
- 序章 Beat 状态机本身（F-05）
- 辅助功能控件 UI（F-07）
- 新的场景资产创作（属于美术资产环节，不是代码特性）

## 验收标准

- [ ] 六章每个相邻章节转场完成后，旧章场景根节点和 Beat 被清除，新章热点正确激活，不同时存在两章的交互热点
- [ ] 转场期间应用失焦或强制退出，恢复后落在最近稳定检查点并确定性重放转场，不出现半透明中间帧
- [ ] 音频混音：镜像空间（第二章）进入时低频共鸣 120Hz + 钟声混响 1.8s 正确叠入，退出时叠出；教室环境音（灯管嗡声/风扇底噪）在非教室场景静默，不串台
- [ ] 方向字幕全局开关在六章全程有效：关闭后所有 `AudioCueKind` 事件字幕不再显示，开启后恢复，不需要重启
- [ ] 系统 Reduce Motion 开启时，`colorTemperatureFlip` 和 `mirrorRipple` 转场替换为 0.2-0.4s 淡入淡出；`fade` 转场时长不变
- [ ] VoiceOver 焦点在 HUD 目标切换后落到新目标元素，不停在已消失的旧元素；在资源卡上时能朗读热线号码并触发复制按钮
- [ ] `SupportResourceCatalog` 审核日期超过 6 个月时：Debug 构建输出 `#warning`，不阻塞 Release 打包
- [ ] 全状态组合测试覆盖设计文档 §必测状态矩阵中所有场景（共 16 组），无重复奖励、无重复台词、无丢失同伴/披露状态

## 设计约束

- 转场三阶段必须原子化：`commit` 以一次事务切换章节、检查点、相机和目标；不得先切场景再补状态
- 转场期间只有 `cleanup` 后才移除旧章节点，`prepare` 阶段相邻场景根预载但热点不开放
- 音频混音不在此特性新增 `AVAudioEngine` 节点图结构，复用 `SpatialAudioManager` 现有接口，只补充缺失的 `AudioCueKind` case 和程序化兜底
- 无障碍修改只调整动画时长和字幕开关逻辑，不改变完成判定时长、Beat 触发时机或剧情写入逻辑
- 所有热点必须支持键盘焦点导航，不能只依赖鼠标悬停（六章全局约束，本特性做最终交叉验证）
