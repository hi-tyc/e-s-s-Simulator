# F-08 视角停留判定与聚焦反馈

> 状态：final / accepted
> 实现阶段：Phase 2
> 依赖特性：F-01（叙事状态机与章节进度）、F-02（SceneDirector 节拍系统）、F-04（叙事相机模式与场景呈现）

## 产品能力描述

为玩家的视角停留行为赋予叙事意义：当苏念视线在某个方向停留足够时间，游戏自动确认"已注意到"并触发该步骤的聚焦完成信号，同时给予画面边缘极淡暖光与轻微推近（FOV −2°，0.5 秒）的视觉反馈。该机制是第一章"看向林澈""听清右侧声音""低头休息"三个核心观察步骤的主要完成路径，也服务于第三章的线索观察，体现本作"停下来注意"而非"快速扫描"的操作语言。

## 功能边界

**包含：**
- `dwellTimer` 逻辑：按帧累计当前 `CameraPose` 的停留时长，切换姿态时重置为 0
- 可配置的每姿态阈值（`DwellThreshold`），初版值：`.left` / `.right` 2.0 秒，`.desk` 3.0 秒
- 暂停期间（`activePauseReasons` 非空）计时冻结，恢复后从冻结点继续累计，不重置
- 阈值触达时：触发聚焦视觉反馈（屏幕边缘极淡暖光 overlay + SCNCamera FOV 推近）并通知 GameManager 调用 `completeStep`
- 幂等保护：同一 `CameraPose` 在同一步骤上下文中只触发一次完成信号
- 机制对键盘/鼠标/触控板输入等效，不区分输入方式

**不包含：**
- 依赖停留触发的具体步骤内容（独白文本、NPC 动作、便签写入）——属于各章节特性
- 30 秒提示引导与 90 秒自动兜底路径——属于 SceneDirector Beat（F-02）
- 方向字幕显示——属于辅助设置面板（F-07）
- 第三人称自由移动、对话锁定、等候视角下的停留判定（这些模式不激活 dwellTimer）
- 微游戏 overlay 内部的手势判定（F-12）

## 验收标准

- [ ] 第一章步骤 1：`CameraPose` 切换为 `.left` 并停留 ≥ 2.0 秒后，`Ch1State.linCheObserved` 置 `true`，聚焦反馈（暖光 + FOV 推近）在 0.1 秒内启动
- [ ] 第一章步骤 2：`CameraPose` 切换为 `.right` 并停留 ≥ 2.0 秒后，`Ch1State.soundObserved` 置 `true`
- [ ] 第一章步骤 3（条件 C）：`CameraPose` 切换为 `.desk` 并停留 ≥ 3.0 秒后，步骤以"自我照顾"路径完成
- [ ] 中途切换视角后再回到原方向，计时从 0 重新开始，不累计历史停留
- [ ] 同一步骤中同一 `CameraPose` 达到阈值后再次持续停留，不重复触发 `completeStep`
- [ ] 触发 `.event` 弹层或 `.pauseMenu` 后恢复，停留累计从冻结时间点继续，不丢失已积累时间
- [ ] FOV 推近动画（0.5 秒）结束后画面恢复原始 FOV，不永久改变相机参数
- [ ] `Reduce Motion` 开启时，FOV 推近和暖光淡入改为 0.2 秒淡入淡出，步骤完成判定时机不变

## 设计约束

- `dwellTimer` 仅在 `NarrativeCameraMode.seatedFirstPerson`（固定座位第一人称）模式下激活；第三人称引导、对话、镜像、等候视角不触发停留判定，以防止非观察意图的停留意外推进主线
- 停留判定基于 `CameraPose` 枚举值（视线朝向离散状态），不依赖鼠标移动速度或摄像机连续角度
- 聚焦视觉反馈是纯呈现层，不参与步骤完成逻辑；步骤完成由 `completeStep` 的幂等门禁决定
- 阈值不可在运行时由玩家调整；无障碍需求通过 SceneDirector 兜底路径（30 秒提示、90 秒自动完成）满足，不通过缩短阈值实现
- `DwellFocusState` 为纯运行时状态，不进入 `NarrativeSave`；读档恢复时停留计时从 0 开始
