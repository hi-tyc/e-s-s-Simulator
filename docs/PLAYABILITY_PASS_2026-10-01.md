## 1. 根因定位（比 §3.3 更具体）

### 1.1 根因 C 的真实形态：关卡一是压力系统的盲区

```swift
// 改造前 GameManager.teacherTurn()
if activeChapter == .silentClassroom {
    if currentTurn < maxTurns { currentTurn += 1 }
    currentPhase = .observation
    updatePerception()
    clampPlayer()
    maybeAddAnomalyMonologue()
    checkPlayerExhaustion()
    return          // ← 后面所有压力分支全部不可达
}
if shouldFakePatrol(...) { ... }        // 关卡一永远到不了
else if shouldRearDoorObserve(...) { }  // 关卡一永远到不了
else if discoveryRisk > 92 { ... }      // 关卡一永远到不了
```

所以把暴露从 +2 提到 +6 也**不会**产生任何后果——数值涨上去也没有东西读它。
P0 的关键不是调数值，而是**给关卡一接上压力循环**。

### 1.2 两个会让主线永久卡死的死锁（已修复）

改造过程中，主线被拉长后暴露了两个**原有的**硬锁。它们在 6 回合主线里
碰不到，主线一长就必然踩中：

**死锁 A：节奏期限永远无法满足。**
第一版把"信号成熟"实现成"第 N 回合可推进"，但 `currentTurn` 在关卡一有
`maxTurns` 上限。期限一旦超过上限就永远不成立，主线永久卡在同一步。
实测：自动游玩 `--auto main` 跑 8 次，**7 次卡在 `inspectNote`**。
→ 改成"还要等几个回合"的倒计时，只依赖玩家行动，不可能卡住。

**死锁 B：自由活动让视角失效。**
`continueAfterEvent()` 原本无条件调用 `applyTimeProgression()`；若那一刻钟点
落在课间，就会启动自由活动。而自由活动期间 `setPose` 是空操作：

```swift
func setPose(_ pose: CameraPose) {
    guard activeRole.isTeacher == false, freeRoam.isActive == false else { return }
```

于是"低头看桌面的纸条"这一步永远无法满足，主线永久卡死。
→ 关卡一不再进入自由活动（它的节奏由主线自己控制），且
`continueAfterEvent()` 在关卡一不再推进时段。

两条都有守卫测试，且验证过"把修复回退后测试会失败"。

### 1.3 根因 A 的真实形态：不是"恢复太强"，是"恢复没有上限"

`深呼吸` 的问题是**可以无限次全额使用**。压力门槛（<30 减半）挡不住真正的
刷法——恰恰是压力高的时候，玩家最需要恢复，也最容易一直按。

→ 改为**同一时段内耐受衰减**（`1.0 / 0.6 / 0.3 / 0.12`），并在进入新时段时
重置。这样"写作业 / 深呼吸交替"仍然能活，但不再能无限回血。

### 1.4 一个隐藏的假象来源：巡逻位置是纯随机数

```swift
let patrolStep = Int.random(in: 1...2)   // 改造前
```

这有两个问题：

1. **设计上**：这个游戏的核心幻想是"靠鞋跟声、粉笔声和停顿算出老师在哪"。
   随机步长让位置变成不可学习的噪音，玩家只能被动反应——而 §4.2 要求
   危险"可预判"，预判的前提是位置可被学习。
2. **工程上**：它是平衡测试数据波动的主要来源（同一策略每次跑出的暴露
   差 12 点），让"用 Agent 模式验证数值"这件事本身不可靠。

→ 改为由 `currentTurn` 和 `巡视频率` 决定的固定节拍。

## 2. 改动清单

### 2.1 关卡一压力循环（P0 核心 / P1 反馈层）

新增 `applyChapterOnePressure()`，把关卡一接进分级压力系统：

| 暴露区间 | 前兆（文本 + 听觉） | 数值代价 |
|---|---|---|
| < 30 | "教室很安静，笔尖声清晰。" | — |
| 30–50 | "有人往你这边看了一眼，也可能只是翻页。" | 压力 +1.5 |
| 50–70 | "老师的脚步变慢了，你被放进了巡视范围。" | 压力 +3.5 |
| ≥ 70 | "你感觉被盯住了，后背发紧。下一步她就会走过来。" | 压力 +6、面具 +2 |

**被抓住不是概率事件。** 越过 70 先给一个缓冲回合，如果下一回合仍留在线上
才会被看见（`triggerChapterOneDiscovery()`）：暴露回落到 46、压力 +14、
面具 +8、记录一次警告，并弹出一个三选一事件（收手 / 承认 / 装回普通学生）。

> 为什么去掉了掷骰子：第一版用 `discoveryRisk` 判定 + 随机数，结果
> 同一策略跑 4 次有 2 种结局，`minEnergy` 在 24 和 38 之间跳。**这既让测试
> flaky，也让"预警"对玩家失去意义**——预警的全部价值就是"我知道下一刻会
> 发生什么，所以我现在要做决定"。改成确定性缓冲回合后，主线一局 12 回合、
> 暴露 73、能量最低 24，四次运行完全一致。

### 2.2 主线铺满整晚（P2 方案 A 的轻量实现）

`chapterOneWaitRemaining` 倒计时：每完成一个主线步骤，下一条线索要等 1 个
回合才会成熟。等待期间玩家必须真的过晚自习。第一章因此从 **6 回合 → 12 回合**。

等待不是惩罚，是设计：等待回合里玩家要写作业、照顾身体需求、承受巡视，
能量和暴露才有时间积累。时机未到时催线索会被拒绝，**但耗损照算**
（暴露、能量、身体需求全部正常结算）——所以"急躁"是有代价的。

### 2.3 数值重平衡（P0 / P3）

| 项目 | 改造前 | 改造后 | 理由 |
|---|---|---|---|
| `观察` 暴露 | +2 | **+6** | 获取信息必须冒险 |
| `观察` 压力 | **-3** | **+1** | 看清楚了不代表压力会下降 |
| `观察` 能量 | -4 | -5 | — |
| **推进主线本身** | 无代价 | **每步 +6 暴露** | 5 步共 +30：认真走主线不再安全 |
| `写作业` 暴露回落 | -4 | **-1.5** | 原来的 -4 足以把主线积累的暴露全部刷掉 |
| `写作业` 能量 | 固定 -11 | **-9/-11/-13/-15 递减** | P3：越写越累 |
| `深呼吸` | 全额可无限刷 | **同段耐受衰减 1.0/0.6/0.3/0.12**，压力<30 再减半 | 消除无脑最优解 |
| `同桌` 暴露 | 近 16 / 远 7 | **近 22 / 远 10** | 支持不是免费的 |
| `传纸条` 暴露 | 近 18 / 远 8 | **近 24 / 远 11** | — |
| 每回合自然消耗 | 无 | **-2.0×疲劳系数**，压力 +1.1×疲劳系数 | P3：人不会凭空平静 |
| 高暴露损耗 | 无 | **暴露>45 时，每点 -0.18 能量、+0.04 压力** | 让"信息→暴露→能量"闭合成环 |

### 2.4 危险可见化（P1）

- **模型层**：新增 `ExposureSignal`（`calm / noticed / watched / targeted`），
  阈值 30/50/70。`exposureSignal` 是唯一数据源，保证提示与真实风险永远同步。
- **文本层**：`updatePerception()` 写入 `dangerSignalText` / `dangerSignalLevel`。
- **GUI 层**：`ContentView.dangerSignalRow` —— 动态变量面板顶部的风险卡片，
  随等级变色（灰→黄→橙→红），并显示"已被记录 N 次"。
- **听觉层**：分级触发纸张声 / 脚步放慢 / 心跳（复用既有 `SpatialAudioManager`）。
- **Agent 层**：`renderSubjectiveState()` 增加"风险前兆"一行——否则 AI 玩家
  看不到这一层，也就无法验证它。

它换来的是"普通的一晚"而不是好结局，因为面具成本低、没有连接、没有推进
主线。让健康的策略"能活下去但不出彩"，比惩罚它更符合这个游戏想说的话。

## 5. 已知问题（留给下一轮，没有擅自改）

### 5.1 `resolveEventChoice` 有两个重复的 `push_through` 分支

Swift 会给出警告 `literal value is already handled by previous pattern`。
两个事件都用了 `push_through` 这个 id：

- 崩溃信号事件（"继续硬撑"）：作业 +8、能量 -15、压力 +18、面具 +8
- 能量见底事件（"继续硬撑"）：面具 +14、压力 +12、能量 +4

后者**永远不可达**。修它需要决定"硬撑"到底应该付出哪种代价——这是设计
决策而不是笔误，所以留给下一轮，没有静默改掉它。

### 5.2 `elapsedMinutes` 与 `currentPeriod` 的时长口径不一致

`elapsedMinutes` 用 `min(settings.totalMinutes, 150)` 计算，而 `currentPeriod`
把**未截断**的 `settings.totalMinutes` 传进去算时段边界。默认 3 小时
（180 分）时，钟点最多走到 150 分，但时段边界按 180 分划分。
后果：`.third` 之前的最后一段时间实际上永远走不到。

这个不一致会让"课间到底落在第几回合"变得反直觉（写测试时踩到过）。
没有改，因为它牵动时段、疲劳系数和课间触发，属于需要单独验证的改动。

### 5.3 关卡一没有课间

因为 §5.2 的时长口径 + 关卡一不推进时段，关卡一全程不会出现课间休息、
饮水机补水、自由活动。玩家只能在座位上应对口渴/饥饿（`喝水` 有 100 上限，
`吃零食` 有暴露代价）。

这是"关掉自由活动"修复的副作用，也让关卡一的资源管理更紧。**但它是有意的
取舍**：关卡一是脚本化切片，开放离座漫游会破坏它的节奏与视角契约。
如果要给关卡一加课间，正确做法是让主线步骤在课间"暂停计时"，而不是打开
自由活动。

## 6. 为什么没做 P2（§4.3 内容量扩张）

§4.3 有两个方案：**A** 让主线贯穿全程；**B** 补齐第二~六章。

- **方案 A 已做**（第 2.2 节）：6 → 12 回合。没有做到 16 回合，是因为
  12 回合已经让能量从 72 掉到 24、暴露爬到 73 并触发一次"被看见"。
  再拉长只会让同一段叙事反复摩擦，而不是增加内容。
- **方案 B 没做**：移植 `freatures/tyc` 的 `NarrativeCampaign.swift`
  是一个数量级更大的任务（六章设计 + 73 个测试 + 大量新事件），
  它应该作为**独立的一轮**来做，而不是附在数值改造后面。

所以 §9.2 的验收项**仍未达成**：

- [ ] 主线贯穿全部 18 回合（当前 12 回合）
- [ ] 至少 3 个章节（当前 1 个）
- [ ] 至少 8 个结局（当前章末 4 个 + 通用 5 个，但只覆盖第一章）

**建议的下一轮顺序**：
1. 补 §5.1 的 `push_through` 决策 + §5.2 的时长口径（都是小改动，但都需要单独验证）；
2. 移植 `freatures/tyc` 的第二、三章，每章都复用本轮的
   `ExposureSignal` + 分级压力循环 + 节奏倒计时三件套；
3. 章节数上去之后再回头校准跨章的能量/暴露曲线（跨章持久化会改变斜率）。
